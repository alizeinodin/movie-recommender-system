## ۱. چکیده

این پروژه یک **سامانهٔ کامل پیشنهاد فیلم** است که از الگوریتم **Neural Collaborative Filtering (NCF)** بر پایهٔ داده‌های **MovieLens 100K** استفاده می‌کند. سیستم در سه لایهٔ **سرویس یادگیری ماشین (Python/FastAPI)**، **Backend (Laravel)** و **رابط کاربری (Nuxt)** طراحی و پیاده‌سازی شده است. کاربران می‌توانند فیلم‌ها را مرور کنند، امتیاز دهند، پیشنهادهای شخصی‌سازی‌شده دریافت کنند و در صفحهٔ جزئیات هر فیلم، فیلم‌های مشابه را مشاهده کنند. در این گزارش، معماری، فناوری‌ها، APIها، قابلیت‌ها و بهبودهای انجام‌شده به‌صورت رسمی و تفصیلی شرح داده می‌شوند.

## ۲. اهداف پروژه

- **پیش‌بینی امتیاز:** پیش‌بینی امتیاز کاربر برای فیلم‌های مشاهده‌نشده در مقیاس ۱ تا ۵.  
- **پیشنهاد شخصی‌سازی‌شده:** ارائهٔ لیست فیلم‌های پیشنهادی برای هر کاربر بر اساس مدل NCF.  
- **پیشنهاد فیلم‌های مشابه:** ارائهٔ فیلم‌های مشابه یک فیلم مشخص (item-based) در صفحهٔ جزئیات.  
- **رابط کاربری شفاف و قابل استفاده:** نمایش فیلم‌ها، امتیازدهی، جزئیات فیلم و پیشنهادها در یک اپلیکیشن وب یکپارچه.  
- **عملکرد و پایداری:** استفاده از کش، پاسخ‌های قطعی و طراحی مناسب برای کاهش بار و افزایش سرعت پاسخ.

│  کش، اعتبارسنجی، Fallback قطعی در صورت عدم دسترسی به ML                 │

┌─────────────────────────────────────────────────────────────────────────┐

## ۵. داده و مدل یادگیری ماشین

### ۵.۱ مجموعهٔ داده

از **MovieLens 100K** استفاده شده است:

- **u.data:** امتیازهای کاربران (user_id، item_id، rating، timestamp).  
- **u.item:** اطلاعات فیلم‌ها (شناسه، عنوان، تاریخ انتشار، ژانرها و غیره).

امتیازها در بازهٔ ۱ تا ۵ هستند. داده به‌صورت ۸۰٪ آموزش و ۲۰٪ تست با seed ثابت تقسیم شده است.

### ۵.۲ مدل NCF (Neural Collaborative Filtering)

مدل بر اساس مقالهٔ **He et al., WWW 2017** پیاده‌سازی شده و دو بخش دارد:

1. **GMF (Generalized Matrix Factorization):** ضرب المان‌به‌المان بردارهای embedding کاربر و آیتم.  
2. **MLP:** الحاق بردارهای embedding کاربر و آیتم و عبور از لایه‌های تمام‌اتصال با ReLU و Dropout.

خروجی نهایی از **ادغام (fusion)** خروجی GMF و MLP و یک لایهٔ خطی به‌دست می‌آید. امتیازها در آموزش به بازهٔ [۰, ۱] نرمال شده و در inference دوباره به مقیاس ۱–۵ برگردانده می‌شوند.

**فایل‌های مرتبط:** `ml-api/src/model.py`، `ml-api/src/train.py`، `ml-api/src/prepareData.py`.

## ۶. لایهٔ سرویس یادگیری ماشین (ML API)

### ۶.۱ نقش و مسئولیت

- بارگذاری **یکباره** مدل و نگاشت‌های کاربر/فیلم.  
- ارائهٔ **پیشنهاد بر اساس کاربر** (top-k).  
- ارائهٔ **فیلم‌های مشابه** یک فیلم (بر اساس embedding آیتم و شباهت کسینوسی).  
- **کش درون‌حافظه** برای جلوگیری از محاسبهٔ تکراری و یکسان بودن خروجی برای ورودی یکسان.

### ۶.۲ Endpointهای سرویس

| متد | مسیر | توضیح |
|-----|------|--------|
| GET | `/health` | بررسی زنده بودن سرویس. |
| GET | `/ready` | بررسی بارگذاری مدل و بازهٔ معتبر user_id. |
| GET | `/version` | نسخهٔ API و وضعیت مدل. |
| GET | `/recommend?user_id=&top_k=` | پیشنهاد top-k فیلم برای کاربر (تعیین‌پذیر و کش‌شده). |
| GET | `/similar?movie_id=&top_k=` | فیلم‌های مشابه یک فیلم (بر اساس embedding؛ کش‌شده). |
| POST | `/recommend/clear-cache` | پاک کردن کش پیشنهاد و مشابه. |

### ۶.۳ بهینه‌سازی‌های عملکرد

- **پیشنهاد کاربر:** به‌جای حلقه روی تک‌تک فیلم‌ها، یک forward pass دسته‌ای (batched) روی همهٔ آیتم‌ها انجام می‌شود.  
- **فیلم‌های مشابه:** بردارهای embedding همهٔ آیتم‌ها یک‌بار پیش‌محاسبه و نگه‌داری می‌شوند؛ هر درخواست similar فقط با یک جستجوی شباهت کسینوسی پاسخ داده می‌شود.  
- **کش:** هر جفت `(user_id, top_k)` و `(movie_id, top_k)` یک‌بار محاسبه و سپس از کش برگردانده می‌شود.

## ۷. لایهٔ Backend و API اصلی

### ۷.۱ پایگاه داده

- **جدول movies:** شناسه (MovieLens)، عنوان، تاریخ انتشار، ژانرها، poster_url، overview، runtime، imdb_id، backdrop_url.  
- **جدول ratings:** user_id، movie_id، امتیاز (۱–۵)، با قید یکتایی (user_id, movie_id).

### ۷.۲ مسیرهای API نسخه ۱ (پیشوند: `/api/v1`)

| متد | مسیر | توضیح |
|-----|------|--------|
| GET | `/movies` | لیست فیلم‌ها با صفحه‌بندی (per_page، page). |
| GET | `/movies/{id}` | جزئیات یک فیلم. |
| GET | `/movies/{id}/rating?user_id=` | امتیاز کاربر برای آن فیلم. |
| GET | `/movies/{id}/similar` | فیلم‌های مشابه آن فیلم (با فراخوانی ML API و کش یکساعته). |
| POST | `/ratings` | ثبت/به‌روزرسانی امتیاز (user_id، movie_id، rating). |
| GET | `/recommendations/{userId}` | پیشنهادهای شخصی‌سازی‌شده برای کاربر (با فراخوانی ML API و کش یکساعته). |

### ۷.۳ جزئیات فیلم و فیلم‌های مشابه

- **فیلم:** فیلدهای اضافه‌شده (overview، runtime، imdb_id، backdrop_url) از طریق Migration و `MovieResource` در پاسخ API برگردانده می‌شوند.  
- **فیلم‌های مشابه:** Backend به ML API با `GET /similar?movie_id=&top_k=12` درخواست می‌دهد، شناسهٔ فیلم‌ها را با رکوردهای جدول `movies` تطبیق می‌دهد و آرایهٔ `movies` را با همان ترتیب برمی‌گرداند. در صورت خطای ML، یک لیست قطعی (مثلاً سایر فیلم‌ها بر اساس id) به‌عنوان fallback برگردانده می‌شود.

### ۷.۴ کش و Fallback

- پیشنهادهای هر کاربر و فیلم‌های مشابه هر فیلم با کلیدهای جداگانه (مثلاً `recommendations:user:{id}` و `similar:movie:{id}`) به‌مدت یک ساعت کش می‌شوند.  
- در صورت در دسترس نبودن ML API، از لیست قطعی (وابسته به user_id یا movie_id) استفاده می‌شود تا رفتار قابل تکرار باشد.

## ۸. رابط کاربری (Frontend)

### ۸.۱ ساختار کلی

- **صفحهٔ اصلی (index):**  
  - هیرو/بنر با تصویر (پوستر یا backdrop) و جزئیات اولین پیشنهاد یا اولین فیلم.  
  - بخش «پیشنهاد شده برای شما» (کاروسل).  
  - بخش «همهٔ فیلم‌ها» با شبکهٔ کارت و دکمهٔ «بارگذاری بیشتر».

- **صفحهٔ جزئیات فیلم (`/movies/[id]`):**  
  - ناحیهٔ بالایی با تصویر (ترجیحاً backdrop_url، در غیر این صورت poster_url یا گرادیان).  
  - عنوان، سال، ژانرها در همان ناحیه.  
  - کارت محتوا: پوستر، امتیازدهی ستاره‌ای، بخش «Overview»، بخش «Details» (تاریخ انتشار، مدت، ژانر، لینک IMDb در صورت وجود، شناسهٔ فیلم، کاربر فعلی).  
  - بخش «بیشتر شبیه این» (More like this) با استفاده از API فیلم‌های مشابه.  
  - دکمهٔ «بازگشت به خانه» با حفظ `user_id` در query.

### ۸.۲ کامپوننت‌ها و Composables

- **AppNavBar:** هدر با واکنش به اسکرول، انتخاب کاربر، لینک خانه.  
- **HeroBanner:** بنر با تصویر، سال، ژانر، دکمه‌های «مشاهده جزئیات» و «امتیاز و پیشنهاد».  
- **CarouselSection، MovieCard، MoviePoster، StarsRate:** برای نمایش لیست‌ها و امتیاز.  
- **useApi:** فراخوانی تمام endpointها از جمله `getMovie`، `getRecommendations`، `getSimilarMovies`، `getMovieRating`، `submitRating`؛ و باز کردن پاسخ `data` برای endpoint جزئیات فیلم.  
- **usePersistedUser، useToast:** مدیریت کاربر پایدار و پیام موفقیت/خطا.

### ۸.۳ اصلاحات مهم در صفحهٔ جزئیات

- **نمایش صحیح داده:** پاسخ API جزئیات فیلم ممکن است در کلید `data` باشد؛ در `getMovie` مقدار واقعی فیلم از `data` استخراج و به صفحه داده می‌شود تا عنوان و بقیهٔ فیلدها درست نمایش داده شوند.  
- **دکمهٔ بازگشت:** استفاده از `NuxtLink` با `path: '/'` و `query: { user_id }` تا بازگشت به خانه با حفظ کاربر انجام شود.  
- **جزئیات همیشه قابل نمایش:** بخش‌های Overview و Details همیشه نمایش داده می‌شوند؛ در صورت نبود overview از متن جایگزین استفاده می‌شود.

## ۱۰. ارزیابی مدل و معیارها

- **RMSE (Root Mean Squared Error):** خطای جذر میانگین مربعات پیش‌بینی نسبت به امتیاز واقعی؛ مقدار کمتر بهتر است (مثلاً زیر ۰٫۹۵ در MovieLens 100K قابل قبول است).  
- **MAE (Mean Absolute Error):** میانگین قدر مطلق اختلاف پیش‌بینی و واقعی؛ مقدار کمتر بهتر است.

دستور ارزیابی از ریشهٔ پروژه:

```bash
source venv/bin/activate
python ml-api/cli.py evaluate
```

خروجی این دستور برای گزارش و ارائه به استاد قابل استفاده است.

```bash
cd backend
cp .env.example .env
php artisan key:generate
php artisan migrate

php artisan serve --port=8001
```

**ترمینال ۲ – ML API:**

```bash
# از ریشهٔ پروژه
source venv/bin/activate
pip install -r ml-api/requirements.txt
python ml-api/cli.py train    # یک بار برای ساخت مدل
uvicorn ml-api.main:app --reload --port 8000
```

```bash
cd frontend
npm install
npm run dev
```

سپس مرورگر را روی **http://localhost:3000** باز کنید.  
می‌توانید از اسکریپت `./scripts/dev.sh` فقط برای چاپ همین دستورات استفاده کنید.

## ۱۲. اصول و بهترین روش‌ها

- **تعیین‌پذیری:** در inference از `model.eval()` و `torch.no_grad()` استفاده شده است؛ کش باعث می‌شود همان ورودی همیشه همان خروجی را بدهد.  
- **اعتبارسنجی:** محدودهٔ user_id (مثلاً ۱–۹۴۳) و مقدار rating در backend اعتبارسنجی می‌شود.

- **لاگ و مشاهده‌پذیری:** middleware در ML API برای لاگ درخواست و مدت زمان؛ در Laravel در صورت خطای ML یک warning لاگ می‌شود.  
- **فرانت‌اند:** تایپ‌های متمرکز، composableهای یکسان برای API و toast، نگه‌داری کاربر در localStorage و همگام با آدرس.
